# Fighter — локальный хост + оверлей

Интерактив для стрима: перед каждым боем зрители голосуют в чате Twitch или Kick, кто победит. Победителя хост выбирает монеткой 50/50 с защитой от длинных серий (см. «Бой»), голоса на исход не влияют. После боя на экране и в чате показывается, сколько зрителей угадали.

Хост — обычный Node-процесс на `127.0.0.1` (Node 22+). **Зависимостей нет**, ставить нечего. Часть с чатом (адаптеры Twitch/Kick, OAuth, релей) взята из «Метеоритного дождя» без изменений.

## Запуск

`fight.bat` (или `node server/index.mjs`). Откроются:

| | |
|---|---|
| Панель стримера | `http://127.0.0.1:7778/` |
| Оверлей для OBS | `http://127.0.0.1:7778/overlay.html?obs=1` |

## Структура

- `server/` — хост, чаты, OAuth, relay и очки.
- `public/` — панель, overlay, leaderboard и только используемые web-ассеты.
- `data/` — рабочий конфиг, балансы, токены и ключ relay; папка не попадает в Git.
- `media/source/` — исходные аудио и видео, не загружаемые в браузер.
- `media/references/` — референсы персонажей и фона.
- `media/archive/` — неактивные варианты медиа.
- `docs/config/` — шаблоны конфигурации.
- `docs/`, `scripts/`, `test/`, `deploy/` — документация, подготовка, проверки и deployment.

## Развёртывание на сервере

Для отдельного контейнера Fighter на VPS с уже работающим релеем и Caddy см. [пошаговую инструкцию](deploy/README.server.md).

Серверный режим рассчитан на публичный HTTPS-домен. Виджет OBS подключается прямо к серверу:

`https://fight.example.com/overlay.html?obs=1`

Минимальная схема:

1. Скопируйте проект на Linux-сервер с Node.js 22+.
2. Создайте `.env` из `.env.example` и укажите `PUBLIC_URL`, например `https://fight.example.com`.
3. Используйте `HOST=127.0.0.1`, если перед Node работает Nginx, либо `HOST=0.0.0.0` для прямого доступа.
4. Настройте Nginx по `deploy/nginx.conf.example` и включите HTTPS.
5. Зарегистрируйте OAuth callback’и платформ как:
   - `https://fight.example.com/auth/twitch/callback`
   - `https://fight.example.com/auth/kick/callback`
6. Запустите приложение через `deploy/fight.service` или Docker Compose.

Для systemd заранее создайте `/opt/fight/data`, скопируйте туда проект и включите сервис:

```bash
sudo mkdir -p /opt/fight/data
sudo cp deploy/fight.service /etc/systemd/system/fight.service
sudo systemctl daemon-reload
sudo systemctl enable --now fight
```

Для Docker:

```bash
cp .env.example .env
# отредактируйте PUBLIC_URL и параметры каналов
# для relay-варианта также задайте KICK_TRANSPORT=relay и KICK_RELAY_URL
docker compose up -d --build
```

Рабочий конфиг, баланс зрителей, OAuth-токены и ключ relay хранятся в volume `fight-data` (или в `data/` при локальном запуске). Файлы `.env`, `data/config.json`, `.tokens.json`, `.agent.json`, `points.json` и их резервные копии не следует добавлять в Git.

Публичный домен из `PUBLIC_URL` автоматически разрешается для Host/Origin-проверок. Дополнительные домены можно указать в `data/config.json` через `allowedHosts`.

`/healthz` — liveness-проверка процесса, а `/readyz` — readiness-проверка: она возвращает `200`, только когда все настроенные чат-адаптеры подключены, и `503`, если один из них ещё подключается или находится в ошибке. Docker healthcheck использует `/readyz`. Административную панель и `/api/*` в публичной установке следует дополнительно закрыть Basic Auth или VPN на уровне Nginx; overlay и leaderboard можно оставить публичными.

В OBS: **Browser Source**, 1920×1080, URL оверлея. Галочку «Shutdown source when not visible» лучше снять.

Порт 7778, а не 7777, — чтобы файтинг и Метеоритный дождь могли работать одновременно.

Демо без хоста: открыть `index.html` двойным кликом (или `overlay.html?solo=1`): бои идут один за другим, клавиши `1` / `2` / пробел / `3`.

## Бой

1. **Ставки** (`voteSeconds`, по умолчанию 30 с): `!1` — на Влада, `!2` — на гориллу, `!3` — без ставки. Один зритель — одна ставка, первая окончательная, сменить её нельзя. Ставят на победителя всего боя.
2. **Бой — как в Mortal Kombat, до двух выигранных раундов.** Хост бросает монетку 50/50 за победителя боя, но против серий: кто выиграл 1 бой подряд, побеждает снова с шансом 40%, 2 подряд — 25%, 3 и больше — 10% (`game.antiStreak` в `data/config.json`, `[]` — обычная монетка). Обе стороны в равных условиях, так что за много боёв всё равно поровну, а серия из 5+ бывает примерно раз в 30 вечеров вместо 2 из 3. Затем хост так же честно решает, отдаст ли проигравший один раунд (2:0 и 2:1 — поровну). Каждый раунд: «ROUND N», гонг и «FIGHT!», 7 ударов примерно за 9,5 с (бывают криты), KO; под полоской здоровья загорается метка выигранного раунда, здоровье восстанавливается. Бой 2:0 идёт около 23 с, 2:1 — около 35 с. Ход боя — `public/js/fight.js`.
3. **Результат**: победитель и счёт раундов, «угадали N из M», выплата очков, в чат — объявление. Экран победы держится, пока стример не откроет следующее голосование (или не отменит бой) в панели.
4. С **автоповтором** экран победы висит не меньше `resultSeconds`. Если репликам и победной анимации нужно больше времени, показ автоматически продлевается; затем через `pauseSeconds` само открывается следующее голосование.

Тайминги звуков находятся в `public/js/fight-media.js`: для каждого файла заданы длительность и отметка акцента относительно попадания. Голосовые атаки Влада A/C и оригинальная реплика идут без случайного изменения скорости; на крите звучит отдельная реплика. После добивания заканчиваются текущие реакции, затем говорит проигравший и через 250 мс — победитель. Отмена боя останавливает звуки сразу. При замене аудиофайлов нужно обновить их длительности и отметки в этом файле.

## Панель

**Персонаж** — кто стоит против гориллы: Влад или второй боец (список — `public/js/roster.js`). Меняется, пока не идут ставки и бой; если висит экран победы, он закрывается. Имя персонажа подставляется в оверлей, чат и панель.

**Серия боёв** — сколько боёв подряд: любое число от 1 до 500 в поле «Серия боёв», затем «Задать» или Enter (пусто или 0 — без серии). На оверлее под таймером счётчик «БОЙ 3/20», перед последним — «ПОСЛЕДНИЙ БОЙ 20/20», в панели — «бой серии 3/20», в чате к объявлению ставок добавляется «Бой 3/20». На каждый бой ставят заново (`!3` — пропустить). Отменённый бой не считается. После последнего боя автоповтор останавливается на экране победы, в чат уходит «Серия окончена»; следующее «Открыть голосование» начинает серию заново, как и «Сбросить счёт». Задать серию можно, пока не идут ставки и бой.

Открыть голосование, «Бой сейчас» (закрыть голосование досрочно, а без голосования — бой сразу), отменить раунд, длительность голосования, автоповтор. Видно голоса по ходу, кто как проголосовал, счёт и историю раундов, статус Twitch/Kick и лог. «Тестовое сообщение» прогоняет голоса без живого чата.

**Защита от серий побед** — внизу карточки «Настройки боя». «Стандартная» задаёт шансы повторной победы 40 / 25 / 10%, «Усиленная» — 35 / 15 / 3%; «Своя» позволяет указать целые проценты от 1 до 99. Последнее значение применяется к серии указанной длины и всем более длинным сериям. Выключенная защита означает независимый выбор 50/50 (`game.antiStreak: []`). Для сохранения нажмите «Применить»: настройка записывается в `data/config.json` (либо файл `CONFIG_FILE`) и сразу действует без перезапуска, сохраняя остальные параметры. Ошибка записи оставляет прежние правила. В Docker файл находится в volume `fight-data`, поэтому настройка переживает пересборку контейнера.

Менять защиту можно в ожидании, на экране результата или в паузе. Во время ставок и боя изменения запрещены и в панели, и на сервере. Вводимые значения не сбрасываются при автоматическом обновлении состояния; для других открытых панелей применённые настройки приходят автоматически. Текущая серия побед при изменении вероятностей не обнуляется.

Блок защиты изначально свёрнут: нажмите строку «Защита от серий побед», чтобы раскрыть настройки. В заголовке показан применённый режим или «Есть изменения» для несохранённого ввода. Сворачивание не выключает защиту и не сбрасывает ввод; при перезагрузке страницы загружаются сохранённые настройки, а блок снова закрыт.

## Команды в чате

Чат только ставит: `!1` · `!2` · `!3` (кто может — `commands.voteRoles`), и записывается в таблицу очков: `!join` (в любой момент, со стартовыми 100 очками — они даются один раз; дальше очки только от стримера). Всё управление боем — в панели.

## Очки

Ставка — весь баланс зрителя: угадал победителя — баланс ×2, не угадал — баланс 0. `!3` и не голосовавшие ничего не теряют. В каждом бою засчитывается только первая ставка зрителя (`!1`, `!2` или `!3`): поменять сторону или поставить на обе нельзя, повторные команды игнорируются. Стартовый баланс — `points.start`, по умолчанию **100**: даётся один раз, когда зритель впервые попадает в таблицу (по `!join` или первой ставке). Проиграл всё — остаётся 0 и не может ставить: его `!1` / `!2` / `!3` не принимаются, в «Голосах» и процентах его нет, пока стример не начислит очки в панели. `0` — стартовых очков нет вовсе, только от стримера. Первая же ставка заносит зрителя в таблицу, после чего ему можно начислить очки по нику. Чтобы у всех новых сразу было, скажем, 100, — `"points": { "start": 100 }` в `data/config.json`. На исход боя ставки не влияют — победителя по-прежнему решает монетка 50/50.

Балансы хранятся в `data/points.json` рядом с хостом (переживают перезапуск; папка игнорируется Git). Топ — в панели («Очки зрителей», там же сброс всем — двойным нажатием). Отдельный оверлей с таблицей для OBS — `http://127.0.0.1:7778/points.html` (прозрачный фон, например 520×720; `?rows=N` — сколько мест показать, по умолчанию 10).

**Начислить очки** можно в той же карточке панели: «Зрителю» — по нику (клик по строке таблицы подставляет ник; регистр не важен, один ник на Twitch и Kick получит оба), «Всем в таблице» — каждому, кто когда-либо ставил, включая тех, у кого 0 (подтверждается вторым нажатием), «Всем процент» — каждому N % от указанной суммы (10 % от 100 000 = по 10 000 каждому; сколько выйдет — видно рядом). Минус — снять очки, ниже нуля баланс не опускается. Начислить можно только тем, кто есть в таблице: написал `!join` или сделал ставку (попадает в таблицу сразу, не дожидаясь конца боя). В панели видны все из таблицы, включая тех, у кого 0; в OBS-таблице — только те, у кого есть очки. Очки сохраняются между боями, сериями и перезапусками хоста. Удаляет зрителей из таблицы только кнопка «Сбросить очки». Перед каждой записью прошлая версия файла копируется в `points.json.bak`: если `points.json` повредится, хост загрузит копию, а сломанный файл отложит как `points.json.broken-…`. Если не читаются оба файла, хост не перезаписывает их, пока вы не почините файл. При закрытии окна хоста, Ctrl+C и падении очки дописываются на диск. Каждое начисление пишется в лог хоста.

Антиспам: 3 голоса / 10 с на зрителя, повтор того же текста в пределах 2 с игнорируется.

## Настройка

**Стримеру, которому дали адрес релея**, достаточно скопировать `docs/config/config.streamer.example.json` в `data/config.json` и указать два ника: свой на Twitch и канал на Kick. Остальное берётся из настроек по умолчанию (полный список — `docs/config/config.example.json`).

Kick идёт через тот же релей, что и Метеоритный дождь (`relay.cigilvpn.store`): хост сам дозванивается до релея исходящим HTTPS, за NAT и фаерволом тоже. В панели — «Подключить Kick» (владелец канала один раз подтверждает доступ — бот сможет и писать в чат) или «привязать по нику» (без владельца, только чтение чата). Ключ агента хост создаёт сам при первом подключении и хранит в `data/.agent.json` (папка в `.gitignore`).

Ограничение релея: один канал Kick привязан ровно к одному агенту. Если на одном канале запустить и Метеоритный дождь, и файтинг, каждая новая привязка забирает канал у другой игры. У разных стримеров с разными каналами конфликта нет.

Twitch читается анонимно — достаточно ника; чтобы бот писал в чат, нужна авторизация (см. README Метеоритного дождя). Redirect URL приложения Twitch/Kick — на порту **7778**, например `http://localhost:7778/auth/twitch/callback`. Имена бойцов — `game.names` (имя Влада и гориллы), свои имена остальных персонажей — `game.characters`, например `"characters": { "fighter2": "ИМЯ" }`; с кем открывается хост — `game.character` (`vlad`, `fighter2` — Павер в белом, `fighter3` — Павер в красном). Стартовые очки — `points.start`.

## Звуки

Гонг — `public/assets/sfx/gong.mp3` (из `media/source/Sound/Heavy_metallic_gong__#1…wav`, вырезан сам удар): звучит на «FIGHT!», музыка входит через 0,6 с под его хвост.

Музыка боя — `public/assets/sfx/fight-music-1.mp3` (из `media/source/Sound/Dark_epic_fighting_g_#1…wav`); прежний трек `#4` лежит рядом как `fight-music-4.mp3`, переключается строкой `MUSIC_SRC` в `overlay.html`. Оба выровнены по громкости (−13 LUFS), так что баланс с ударами при замене не меняется. Музыка стартует с «FIGHT!», после KO за 1,8 с затихает; в оверлее она на 6% и на каждом ударе на долю секунды приглушается — уровни задают `MUSIC_LEVEL` и `DUCK_LEVEL`.

Звуки Влада из `Downloads/Влад Звуки` подключены через `sfx` в `public/js/roster.js`. Для обычной атаки используются три варианта. Одобренные A и C из «Звук удара 2»: `vlad-attack-a.mp3` (0,48–1,18 с исходника, ускорение 1,05×) и `vlad-attack-c.mp3` (2,34–3,28 с, ускорение 1,4×) звучат около 0,67–0,68 с и совпадают с версиями `a-fit.mp3` / `c-fit.mp3` из `docs/audio-review/vlad-attack2`. Третий вариант — `vlad-attack-original.mp3` из «Звук удара.ogg» (0,56–1,70 с, длительность 1,14 с, без ускорения, усиление 2 dB): сохранена вся реплика с запасом по краям. Все три выбираются без повтора подряд и воспроизводятся со скоростью 1×, включая добивание; каждому задан собственный момент акцента. B и прежний `vlad-attack-complete.ogg` не подключены.

`vlad-crit-complete.ogg` — целая запись крита (около 1,33 с, ускорение 1,4×), `vlad-hurt-1..7.ogg` — реакции на урон, `vlad-win.ogg` и `vlad-defeat.ogg` — победа и поражение во всём бою. Ускорение при подготовке выполняется через `atempo` без изменения тона. Звуки следуют за Владом в любой угол. При отмене боя проигрываемые голосовые реакции останавливаются. Подготовку можно повторить: `node scripts/prepare-vlad-sfx.mjs "C:\Users\goman\Downloads\Влад Звуки"` (нужен FFmpeg). Для пересборки только нового звука добавьте последний аргумент `vlad-attack-original`.

Удары гориллы — тяжёлый замах `gorilla-swing-1..2.mp3` (из `Massive_heavy_whoosh_#1` и `#4`): он стартует вместе с рывком и достигает пика в момент попадания; поверх в момент попадания — глухой удар (прежние `vlad-punch-1..3.mp3`, нарезанные из `media/source/Sound`, с пониженной высотой), потому что сам свист почти весь в басах и на небольших колонках не слышен.

Когда боец попадает по горилле, она взвизгивает — `gorilla-yelp.ogg` (из `Massive_gorilla_yelp_#4`), при любом персонаже. Высота слегка гуляет, на крите и KO звук громче и ниже. На своей атаке горилла ревёт — `gorilla-roar.ogg` (второй, длинный крик из `Massive_gorilla_yelp_#1`): рёв начинается на замахе, его пик — за 0,2 с до удара.

Когда горилла выигрывает бой, она запрокидывает голову и ревёт: клип `assets/anim/gorilla-win.webm` (4 с, из `Downloads/0619959a…mp4`, зелёный фон) со звуком `gorilla-win.ogg` (из `Epic_gorilla_victory_#3`: два крика, пауза между ними вырезана). После рёва горилла возвращается в обычную стойку.

Звуки Павера (оба наряда, `sfx` в `public/js/roster.js`) — `paver-punch-1..3.ogg` вместо ударов Влада (по очереди вразброс), `paver-crit.ogg` — выкрик на крите (начинается вместе с анимацией супер-удара, громче всего на попадании; удар при этом тоже звучит), `paver-hurt-1..3.ogg` — стон, когда горилла попадает по нему (сразу после удара, подряд не повторяется), `paver-win-1..2.ogg` — возглас при победе в бою (один из двух). Нарезаны из `Downloads/Звуки`: тишина в начале убрана, громкость выровнена.

Громкость — микшером OBS (в свойствах источника можно включить «Control audio via OBS»), либо параметром оверлея: `overlay.html?obs=1&volume=0.5`, `&mute=1` — без звука. В обычной вкладке браузера звук включится только после клика по странице; OBS играет сразу.

Реакции на урон у всех персонажей дополнительно приглушены коэффициентом `HURT_LEVEL = 0.7` в `overlay.html` (около −3,1 dB относительно прежнего уровня). Звук атаки остаётся главным; на крит и KO реакция по-прежнему сильнее, чем на обычный удар. Громкость победных и проигрышных реплик задаётся отдельно.

Финальные реплики звучат по очереди: сначала поражение, затем после окончания записи и паузы 250 мс — победа. Если у проигравшего нет реплики, победитель начинает через 450 мс. Победная анимация гориллы запускается вместе с её рёвом. Отмена боя или новое голосование прерывают очередь; ошибка аудио не блокирует следующую реплику.

## Анимации

`public/assets/anim/vlad-idle.webm` — стойка, петля 10 с (ролик idle сыгран вперёд и назад, чтобы не было шва). `public/assets/anim/vlad-kick.webm` — удар ногой, 1,08 с (из 5 с исходника: стойка в начале промотана, зависание ноги сокращено, в конце 3 кадра перехода обратно в стойку). Оба — VP9 с прозрачностью; фон вырезан только там, где тёмное касается края кадра, поэтому чёрная одежда цела. Исходники с чёрным фоном и ускоренный удар в MP4 — в `media/source/Anim`.

Каждый удар Влада — этот удар ногой: он стартует за `contactMs` (520 мс, таблица `ANIM` в `overlay.html`) до попадания, дальность рывка — `--reach-kick`. Если видео не играет, остаётся `fighter.png` с покачиванием.

`public/assets/anim/gorilla-idle.webm` — стойка гориллы, петля 10 с «вперёд-назад». Тёмная шерсть на чёрном фоне сливается, поэтому при вырезке подсказкой служит силуэт `gorilla.png` (та же картинка в масштабе 0,946): в глубине силуэта фон не вырезается вовсе, у его края — только совсем чёрное.

`public/assets/anim/gorilla-attack.webm` — удар гориллы, 0,92 с (из 5,2 с исходника: стойка промотана, рёв и подъём на задние лапы в 4 раза быстрее, выброс лапы в 2 раза, затем подъём в обратную сторону — обратно на четыре лапы — и сведение с кадром 1 idle). Исходник снят на другом холсте (704×928), кадры пересчитаны на холст idle (масштаб 1,17, сдвиг 12/2 px — по совпадению силуэтов). Лапа на полном вылете на 540-й мс, дальность рывка — `--reach-swing`. Звуковую дорожку ролика (рёв) не используем. Ускоренная версия на чёрном фоне — `media/source/Anim/gorilla-attack-fast.mp4`.

`public/assets/anim/vlad-punch.webm` — обычный удар Влада, прямой рукой, 0,88 с (из 5,2 с исходника: стойка обрезана, замах и выброс руки вдвое быстрее, затем замах в обратную сторону — обратно в стойку). Холст исходника 704×768 пересчитан на холст idle (масштаб 1,2925, сдвиг 17/−1). Удар ногой (`vlad-kick.webm`) теперь — крит Влада.

`public/assets/anim/gorilla-crit.webm` — крит гориллы, удар двумя кулаками о землю, 1,29 с: замах подольше, стоп-кадр (3 кадра) в момент удара о землю, пыль на полной скорости. Поднятый кулак выходит за угол исходного кадра — края справа и сверху растушёваны; почти прозрачная тёмная дымка фона вычищена, иначе CSS-тень рисует вокруг гориллы тёмный прямоугольник.

`public/assets/anim/vlad-defeat.webm` — Влад проиграл весь бой: сгибается, рвёт футболку, плачет; 5,1 с, затем последний кадр держится. Играет вместо затемнения только на KO последнего раунда. Фон исходника — ровная серая заливка (22), поэтому вырезан по точному цвету фона, а не по тёмному. Надпись «… WINS!» на экране победы через 1,2 с уменьшается и уезжает под полоски здоровья, чтобы не закрывать бойцов.

**Второй боец** (`fighter2`): `public/assets/fighter2.png`, `anim/f2-idle.webm` — стойка, петля 10 с «вперёд-назад» (исходник на чёрном фоне; снят только тёмный ореол по краю, светлая обводка оставлена), `anim/f2-punch.webm` — шаг вперёд и прямой, 0,83 с: стойка, шаг с ударом (рука полностью на 292-й мс), рука держится, затем те же кадры назад — шаг обратно в стойку. Фон ролика удара плавно меняется с чёрного на белый, поэтому вырезка идёт по кадрам: фон каждого кадра оценивается заново, кадры, где он ещё переливается, не используются. Край маски сглажен (иначе там, где белая футболка встречается с белым фоном, выходили «лесенки»). `anim/f2-crit.webm` — крит, 1,33 с: крик и замах (ускорены в 4 раза), кулак отводится назад, выпад прямым (рука полностью на 583-й мс), стоп-кадр 3 кадра в момент удара, затем возврат в стойку вдвое быстрее; долгое «дожимание» руки из исходника вырезано. Удар идёт на уровне головы, поэтому рывок у крита короче, чем у обычного удара. Своей анимации поражения у Павера пока нет — при проигрыше он затемняется.

**Павер в красном** (`fighter3`, в панели «ПАВЕР — Красный»; белый — «ПАВЕР — Белый»): `public/assets/fighter3.png`, `anim/f3-idle.webm` — стойка, петля 9 с «вперёд-назад», `anim/f3-punch.webm` — замах и прямой, 0,83 с (рука полностью на 333-й мс; дальше в исходнике кулак уходит за край кадра, поэтому попадание — чуть раньше), затем те же кадры назад в стойку. Оба исходника сняты на зелёном фоне: вырезка хромакеем — прозрачность по тому, насколько зелёный перевешивает, плюс удаление зелёного отсвета; в начале роликов фон проявляется из чёрного, пороги считаются по фону каждого кадра. `anim/f3-crit.webm` — крит (супер-удар), 1,21 с: короткий прямой для разгона (в 3 раза быстрее), отвод руки, выпад всем телом (рука полностью на 583-й мс), стоп-кадр 3 кадра на ударе, затем возврат в стойку; долгое удержание руки из исходника вырезано. Своей анимации поражения пока нет.

Персонажи и их ролики — `public/js/roster.js` (`attack`, `crit`, `defeat`, `contactMs`, дальность рывка `reach`). Ролики гориллы — таблица `ANIM` в `overlay.html`.

Какой ролик играет на каком ударе — таблица `ANIM` в `overlay.html` (`attack` — обычный удар, `crit` — крит, `defeat` — поражение, `contactMs` — где в ролике момент попадания). Дальность рывков — `--reach-punch`, `--reach-kick`, `--reach-swing`, `--reach-slam`.
